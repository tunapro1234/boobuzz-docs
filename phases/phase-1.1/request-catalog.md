# Request catalog (robot-code `dev-phase-1.1`)

Source root for every citation: `TeamCode/core/src/main/java/boobuzz/core/` in
robot-code commit `aca0f19`.  A request is immutable: `params` is a copied
`double[]`; only `PATH` may carry a `PathRequest`
(`contract/Request.java:6-17`).  Statuses produced by `act` are drained into
the controller's next-tick `Feedback`; there is no current `ACCEPTED` emitter
(`contract/RequestStatus.java:3-23`, `logic/IRobotEngine.java:31-33`).

## RequestStream and batch fields

`RequestStream` is a level message, not a request: `vx`, `vy`, and `omega` are
the three drive commands (the teleop map applies deadband/field rotation), and
`manualDrive` grants manual-drive ownership.  It has no ID or status
(`contract/RequestStream.java:3-12`).  `RequestBatch` carries one stream, an
immutable request list, and integer request IDs to cancel; `Integer.MIN_VALUE`
means `CANCEL_ALL` (`contract/RequestBatch.java:5-15,29-30`).  DirectEngine and
cplx1 `MotionLogic` consume the stream; manual input cancels active motion and
an idle non-manual stream stops the drive (`logic/direct/DirectEngine.java:53-87`,
`logic/cplx1/MotionLogic.java:25-60`).

The catalog intentionally records implementation gaps rather than inferring
behavior: `RESET_POSE` is emitted but unhandled, cplx1 does not honor
individual shooter cancel IDs, and `RequestStatus.ACCEPTED` is defined but not
currently emitted.
